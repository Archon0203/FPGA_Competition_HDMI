# 12 · 显示器 UI / 叠加层设计（理论分析，暂不实现）

> 本文**只做设计分析**，不写代码。目标：在 640×480@60 的 HDMI 输出上，用 FPGA 硬件给“信息发布与应急广播终端”配一套**分层叠加式 UI**，与现有 RTL 模块（vga_timing / color_space / image_scaler / image_enhance / transition / osd_overlay / audio_visual / menu_fsm / app_scenario）衔接。

## 0. 结论先行

EG4S20 没有 GPU、没有 OS，**不做窗口系统**。UI = 在“基础画面（图片/短视频）”之上，按优先级叠加**硬件生成的几个图层**：

```
  [应急整屏]      (最高)
  [OSD 文字层]    (状态栏/时间/滚动标语/参数)
  [音频可视化]    (底部振幅条)
  [基础画面]      (帧缓冲内容，经缩放/增强/转场)
```

每层独立输出“像素有效 + 像素值”，由一层**组合优先级 mux** 自上而下选中最优先层；UI 状态由 `menu_fsm`/`app_scenario` 驱动，慢速参数用 clk_pix 侧寄存，规避跨时钟域亚稳态。

---

## 1. 设计目标与约束

### 1.1 目标

- 明确传达“终端”状态：当前内容（图号/片段号）、播放/暂停、当前时间、模式（常态/应急）、亮度/对比度/转场档位。
- 突出“应急广播”场景：一键进入整屏警告，毫秒级、无卡顿。
- 复用已有纯 RTL（osd_overlay + 字库、audio_visual、image_enhance、transition），不引入新 CPU/IP。

### 1.2 硬件约束

- 输出 640×480@60，像素时钟 ~25.175MHz；**无 GPU/CPU**，逐像素组合。
- 资源 19600 LUT；**不投入完整 FFT / 抗锯齿 / 半透明混合**（太贵）。
- 文字用 8×16 点阵字库 ROM（ERAM 约 32KB），只能用 **1~2 种前景色**（如白字、红字），不做阴影/描边。
- 跨时钟域：UI 状态来自 `clk_sys`（50M），显示在 `clk_pix`；慢速字段在 clk_pix 侧双拍寄存即可，事件类走 `async_fifo`。

---

## 2. 图层与分区（自上而下）

| 优先级 | 图层 | 区域 | 内容 | 来源模块 |
|---|---|---|---|---|
| P3 | 应急整屏 | 全屏 | 红/黑底 + 大字“应急” + 警示图形（可选蜂鸣提示） | app_scenario(emergency) + osd_overlay / 应急页 ROM |
| P2 | OSD 文字层 | 顶部状态栏(0..23) + 底部滚动条(456..479) + 右下参数面板 | 时间 HH:MM:SS、模式、图号、播放状态、亮度/对比度/转场、滚动标语 | osd_overlay + 字库 ROM + 字符 ROM + menu_fsm |
| P1 | 音频可视化 | 底部或右下（如 x=560..） | 振幅包络柱状条 | audio_visual |
| P0 | 基础画面 | 全屏 | 图片 / 短视频帧，经缩放→增强→转场 | frame_buffer_manager + line_prefetcher + line_buffer_pingpong + image_scaler + image_enhance + transition + color_space |

> P0 是“视频/图像”；P1/P2/P3 是“UI 叠加”。P3 与 P2 通常互斥（应急时隐藏状态栏细节，只留大字与警示）。

### 2.1 布局示意（文字线框）

```
0    ┌────────────────────────────────────────────┐
     │ 状态栏: 10:24:31  常态  图003/020  ▶ 播放     │   ← P2 顶部
24   ├────────────────────────────────────────────┤
     │                                            │
     │              基础内容区(缩放/增强)            │   ← P0 全屏
     │                    [音频振幅条]             │   ← P1 右下 (P2 参数面板可用同区)
     │                                            │
456  ├────────────────────────────────────────────┤
     │ 滚动标语: 欢迎光临… 请注意电梯安全…             │   ← P2 底部
480  └────────────────────────────────────────────┘
应急时: P3 整屏“⚠ 紧急通知 ‼”覆盖全部
```

## 3. 各图层渲染方式（与现有模块衔接）

### 3.1 P0 基础内容

- 读帧缓冲（图片双缓冲 / 视频三缓冲）→ `image_scaler` 适配到 640×480 → `color_space`（YCbCr→RGB）→ `image_enhance`（亮度/对比度）→ `transition`（切换时 A/B 混合）。
- 这一层已是成品，UI 只需给它“放行”。

### 3.2 P1 音频可视化

- `audio_visual` 已实现：对 PCM 采样做峰值包络（攻击快/释放慢），在指定 x 区域画一竖直柱，`vis_on` 逐像素生效。
- 扩展：可做 **N 根柱**（N 个窄 x 段，各自包络/频带）——若做简易频谱，用多带上采样 + 幅度平均，而非完整 FFT。
- 颜色：单色（如亮绿）即可；透明区透传 P0。

### 3.3 P2 OSD 文字层（扩展①④）

- `osd_overlay` 已实现“一个 8×16 字形叠加”。要渲染**一行动态文字**，需扩展为：`char = (x - osd_x)/8`，`row = y - osd_y`，按 char 序列从 **字符 ROM** 取字形。
- 静态文本：每字符占 8 列；`menu_fsm` 给出当前字符串（图号、模式、档位）。
- 时间：`clk_sys` 计数秒/分/时（BCD），由 UI 控制器编码为字符索引。
- 滚动标语：每帧把 `osd_x` 偏移 -1 列，实现平滑滚动（帧级移动，不闪）。
- 参数面板：亮度/对比度/转场档位，用“标签 + 短条”或直接文字“对比 2.0×”。

### 3.4 P3 应急整屏

- `emergency` 置位时，P3 整屏用**应急页 ROM**（大字 + 警示色），叠加在一切之上；`beep`/`dual_led` 联动。
- 应急页内容固定（文字/图形），用 ROM 或 OSD 大字方式渲染，保证切换确定性、低延迟。

## 4. 合成与优先级

### 4.1 逐像素混合

对每个像素 (x,y)：从上到下判断各层是否“覆盖该像素”；取最高优先级覆盖层的像素值，否则透传。

```
pix_out = P3_en ? P3_px :
          P2_en ? P2_px :
          P1_en ? P1_px :
          P0_px;
```

- 每层输出 `layer_cover`（是否命中）+ `layer_px`。
- 组合 mux 只需少量比较/选择，无半透明，资源低、组合路径短（单像素时钟内完成）。

### 4.2 层使能

- `P3`：`app_scenario.emergency`。
- `P2`：`osd_en`（用户可关）+ 各子区是否在显示区域（状态栏/标语/参数面板）。
- `P1`：`audio_vis_en`（可在 SW 或菜单开关）。

---

## 5. 交互与状态映射

复用 `menu_fsm`/`app_scenario` 已有输出，扩展为 UI 字段：

| 输入 | 影响 | UI 体现 |
|---|---|---|
| KEY0 | 播放/暂停 | 状态栏“▶/⏸”，内容冻结/恢复 |
| KEY1/KEY2 | 上/下一张或片段 | 图号/片段号更新 |
| KEY3 | 进入/退出应急 | P3 整屏 + 蜂鸣 |
| SW0-1 | 转场模式 | 参数面板“转场: 无/淡/擦” |
| SW2-3 | 亮度/对比度档 | 参数面板“亮度 + / 对比 ×” |

这些字段变化慢（帧级/按键级），在 `clk_pix` 侧寄存即可；跨时钟域只需对 `key_event` 等事件走 `async_fifo`。

---

## 6. 数据流与时序

```
clk_sys(50M): menu_fsm / app_scenario -> 状态字段(槽位寄存器)
                 | (事件 async_fifo / 慢速双拍寄存)
clk_pix(25.175M): vga_timing(de,x,y)
                 -> frame_buffer_manager -> line_prefetcher -> line_buffer_pingpong
                 -> scaler -> color_space -> enhance -> transition  (P0)
                 -> audio_visual(P1) / osd_overlay+字库(P2) / emergency(P3)
                 -> 优先级 mux -> hdmi_video_adapter -> APUG092 -> HDMI
```

- 像素时钟内只做：读层、判命中、优先级选择；不读外部慢速接口。
- 时间、标语等更新在 `de` 帧边界（VSync 前后）触发，避免行内撕裂。

---

## 7. 资源估算（粗）

- 字库 ROM：8×16 × ≤256 字 ≈ 32KB ERAM（可用）。
- 字符/文案 ROM：少量。
- 每层命中逻辑 + 优先级 mux：个位数 LUT/像素；可满足 19600 LUT 预算。
- 音频柱：`audio_visual` 已实现，几乎零额外资源。

---

## 8. 与评分点对齐

| 评分项 | UI 对应 |
|---|---|
| 基础①核心功能 | P0 内容区正常显示/切图/轮播 |
| 基础④工程规范 | 分层组合、时钟域标注、注释/文档 |
| 扩展①字幕 | 顶部状态栏 + 底部滚动标语 |
| 扩展④实时调节+OSD | 参数面板显示亮度/对比度/转场 |
| 扩展⑤音频可视化 | 底部振幅条 |
| 应急场景 | P3 应急整屏（毫秒级确定性） |

---

## 9. 非目标（避免踩坑）

- 不做窗口管理/任意窗口拖动、无圆角/阴影/半透明/抗锯齿。
- 不做完整 FFT（用包络/多带近似）；不做过度精细的滚动“平滑插值”（帧级即可）。
- 应急/转场优先确定性，不做高开销过渡。
- 视频流不叠过多复杂元素，避免争抢 LUT 与带宽。

---

## 10. 建议实现顺序（后续）

1. **状态栏 + 时间**（时间计数 + osd 文字行）——纯 RTL，先仿真。
2. **滚动标语**（字符 ROM 偏移 + 每帧滚动）。
3. **参数面板**（亮度/对比度/档位文字 + 短条）。
4. **音频柱接入 P1**（audio_visual 已具备，接入优先级 mux）。
5. **应急整屏 P3**（与 app_scenario.emergency 联动）。
6. 集成到 `mini-top` 显示链（含优先级 mux）做仿真联调。

> 每步对应一个纯 RTL 模块/扩展，均可独立 `tb` 仿真 PASS；具体端口与模块名在实现阶段确定。
