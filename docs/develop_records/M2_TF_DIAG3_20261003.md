## Board evidence entering this revision

- `tb_m2_real_media_uart_bridge`: PASS, checks=5, Errors=0, Warnings=0.
- Board: yellow startup page, then fault page; physical LED1 + LED3 remain lit.
- Uploaded routed TD6.2.1 STA: SWNS=-7.098 ns, STNS=-337.114 ns, HWNS=+0.004 ns.
- 150 MHz controller self-domain itself passes with SWNS=+0.938 ns. The negative setup is entirely the APUG011 `clkc[1] <-> clkc[2]` hard-SDRAM DQ boundary.

## Changes

1. Restore the board-proven P1-05A SDC policy in `constraints/slave/slave.sdc`: explicit 25 MHz/150 MHz asynchronous clock group plus the two narrowly scoped APUG011 phase-boundary false paths. No 150 MHz controller RTL path is excepted.
2. Remove the DIAG2 19-bit accepted-word counter. Resource-sensitive diagnosis now uses only the existing error registers and four LEDs.
3. `p1_media_framebuffer_loader` now assigns a nonzero terminal detail if a transaction fails without an earlier detailed protocol code:
   - 1: file reader terminal failure
   - 2: pixel decoder terminal failure
   - A: metadata/geometry rejected
   - B: writer never armed
   - E: writer terminal count/result mismatch
   - F: other terminal consistency failure
4. `m2_real_media_service` no longer emits ambiguous legacy `0x15`; a zero protocol detail falls back to `0x3F`.
5. Board fault presentation is direct and low-cost: LED low nibble + HDMI high-nibble family color.

## Fault display after the initial yellow page

- RED + LEDs `n` -> error `0x1n` (service/sector/file family).
- MAGENTA + LEDs `n` -> error `0x2n` (catalog/selection family).
- CYAN + LEDs `n` -> error `0x3n` (loader/writer detail family).
- WHITE + LED `F` -> SDRAM backend sticky fault.

Normal non-fault LED status remains `{0, media_busy, frame_ready_sdr, media_catalog_valid}`. Therefore yellow + physical LED1/LED3 is a normal `0101` load-in-progress status and must not be interpreted as error code 5.

## Resource note

The existing project area evidence shows the largest low-level LUT consumers are `line_buffer_pingpong` (~4449 LUT) and the generic `m2_media_write_cdc/async_fifo` (~1141 LUT). Do not add more wide board-debug counters. After the 640x480 TF path is functional, the next resource milestone is a BRAM-backed ping-pong line buffer and right-sized CDC FIFO before 1080p/UI expansion.
