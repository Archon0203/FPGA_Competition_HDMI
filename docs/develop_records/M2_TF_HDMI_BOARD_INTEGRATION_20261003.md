## Official example comparison and next board diagnostic

- The user reports that the repaired no-card image is red with moving yellow bands, while the inserted card alternates red and yellow. This indicates retries but does not identify the failure stage. The Slave top now retains the red fault screen while retrying in the background; red clears only after a complete BMP load. The four LEDs show a fault class while red: logic value `1` = sector/SPI scan failed (`0x11`), `2` = FAT32 scan rejected (`0x12`), `3` = descriptor/load precondition (`0x13`), `4` = sector read during BMP load (`0x14`), `5` = loader protocol class (historically `0x15`), `6` = overflow (`0x16`), `7` = BMP load/source failure (`0x17`), `8` = valid catalog but no BMP (`0x20`), `F` = SDRAM backend error. The four-LED group was later confirmed active high. With no fault the prior state mapping is retained.
- The official `lab_ex4_tf` SPI engine uses a CS-high `0xff` byte before each command, then selects the card and uses SPI mode 3. `sd_reader` and the sector provider now use the same command boundary; the M2 Slave TF top selects mode 3. The generic `sd_spi` mode 0 path remains available for its existing tests. Both modes have dedicated Questa byte-level tests, and the M2 SPI bit-level card model now runs in mode 3. No claim is made that the two engines are electrically identical.
- The official BMP reader searches raw physical sectors for BMP headers. This project's media contract instead indexes FAT32 directory entries. In addition to the existing FAT32 MBR partition path, `fat32_scan` now accepts a FAT32 volume whose boot sector is directly at LBA0, with a valid 512-byte BPB and `55 AA` signature. It still requires SDHC block addressing, a BMP 8.3 directory entry in the first root cluster, and the documented 640x480 RGB24 BMP format. A card that works in the official raw-sector scanner is not automatically proof that its directory layout meets this contract.
- Questa 10.7c passes the MBR and LBA0 FAT32 scanner tests, the bit-level SPI-to-image-write tests for both layouts, no-card retry/error, existing media service, and 307200-pixel BMP frame test. The 36 enabled Slave Verilog sources compile with zero errors. No new routed STA, bitstream, or board result is claimed for these changes.
- For this single-image Slave HDMI gate, one valid 640x480 BMP in the first root-directory cluster is sufficient; the four-file requirement in the M2 plan belongs to the later image-selection demonstration. The official example BMP files inspected in `lab_ex4_tf/doc/TF卡图片` have 921654 bytes, 54-byte pixel offset, 640x480 dimensions, 24-bit pixels, and no compression.

## Third board report: LED1 and LED3 on, solid red with TF card

- Rechecked `6_EX_DEVICE.pdf` and `2_FPGA.pdf`: the onboard four-LED group is LED1..LED4 driven by FPGA `LED0..LED3` through 1 kOhm resistors to LEDs returning to GND. It is active high. The ADC maps logic bits `led[0..3]` to `A4, A3, E13, B12`. The separate eight-LED group is not the diagnostic output wired by this top. Physical LED1 and LED3 on means logic `0101`; with a red screen this is fault class 5, not a captured full error byte.
- The older generic `0x15` loader-protocol class could result from `pixel_valid && !pixel_ready` or an overlapping loader start. The physical sector provider formerly replayed its 512-byte RAM at one byte per 25 MHz cycle with no downstream backpressure. A long SDRAM write stall fills the writer's 32-pixel FIFO, then loses pixels; both `protocol_error` and `overflow` become set, but error selection previously reported `0x15` first. This is a reproducible mechanism consistent with the earlier board symptom, not a captured on-board trace or a proven sole cause.
- The media service now pauses sector-RAM replay when the writer FIFO approaches full, retaining four slots for pipeline bytes. Scan and FAT lookup remain unthrottled. The loader clears the previous transaction's protocol flag on every new start; overflow now reports `0x16` ahead of generic protocol error if a real overrun persists.
- The complete 640x480 modeled BMP regression now stalls the write sink for 1600 of each 4096 media clocks. It verifies all 307200 writes, address and RGB content while observing over 600000 paused sector cycles. MBR and LBA0 bit-level TF tests, no-card retry and media-service regression pass. The bit-level TF model also checks that sector index and `din_valid` hold during an imposed pause. The model does not replace real-card testing or routed STA.

## Cable decision

- The current 640x480 TF-to-HDMI hardware gate does **not** require a 40-pin cable; the TF card is local to Slave and the first display test is local Slave HDMI.
- For a later dual-board media link, eleven Dupont wires can carry `GND`, crossed UART TX/RX, one forwarded media clock and seven media data bits. This is a bring-up path for static frames and low-rate packets, not a 1080p60 raw-video link.
- The recommended final arrangement is **two 40-pin groups/cables**: one group reserved for source-synchronous media data with enough ground returns, and one group for SPI control, credit, reset/status and debug. A single 40-pin group can be made to fit a reduced design, but leaves little room for ground returns and control expansion and is not the preferred 1080p/video layout.
