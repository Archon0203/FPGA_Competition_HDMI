# P1-05A Closeout Record — 2026-09-12

> 本文件是开发过程记录，不是状态权威。最终状态以 `docs/03_plan_and_status.md` 为准。

## 1. 阶段目标

P1-05A 的目标是把固定 RGB888 framebuffer 真正写入 EG4S20 internal SDRAM，再通过真实 APUG011、CDC、整行预取和 HDMI_B 输出，且保持 P1-04C HDMI golden boundary 不变。

## 2. 新增/关键模块

### `p1_framebuffer_pattern_writer.v`

150 MHz 域固定帧初始化器。写入 640×480、stride=640、base=0 的 `0x00RRGGBB` 图案：白边、四色象限、洋红竖条、青色横条。

最终 unit：`PASS(259)`。

### `p1_sdram_read_cdc_bridge.v`

25 MHz display request ↔ 150 MHz SDRAM response 的 ordered CDC。request/response 均通过 async FIFO；150 MHz 侧有 registered request boundary。

最终 unit：`PASS(13)`。

### `line_prefetcher` / `line_buffer_pingpong`

P1-05A 复用 P0 行预取/双行缓存。启动调试中发现：line0/line1 warm-up 后两个 bank 均占用，scheduler 若立即启动 line2，会在 `S_WAIT_BUFFER` 中等 bank，并可能在下一 frame boundary 前触发 8192-cycle watchdog。最终规则：只有 `lb_fill_ready=1` 才发 `prefetch_start`。

### `hdmi_framebuffer_scanout.v`

与 P1-04C 800×525 raster 同相调度 line-buffer read，使连续 RGB 对齐 active-video cadence。

最终 unit：`PASS(35)`。

### `p1_sdram_cached_adapter.v`

P1-05A 专用 sequential-video adapter，P1-02 `sdram_adapter.v` 保持冻结。

读取侧：一次 cache miss 读取 aligned 4-word APUG011 group 并缓存全部 lane，随后 3 个连续 lane 命中缓存；解决 single-word adapter 对连续 framebuffer 的 4×物理读放大。

写入侧：最终 timing 版本增加 one-entry registered write request slice。上游 valid/ready handshake 后锁存 addr/data，APUG011 后续 4-word masked transaction 不再组合依赖 writer payload。

最终 unit：

```text
PASS(58)
abstract_reads=8
app_reads=8
hits=6
misses=2
```

### `p1_sdram_hdmi_pipeline.v`

组织 CDC、prefetch、line buffer、scanout；早期小尺寸 test raster 会夸大固定 CDC/FSM latency，修正为 25 MHz pixel、约 150 MHz SDR、64 active + 16 blank 后通过。

最终：`PASS(258)`。

### cached provider integration

```text
p1_sdram_hdmi_pipeline
 -> sdram_arbiter
 -> p1_sdram_cached_adapter
 -> mock_apug011_app_port
```

最终：`PASS(260), pixels=256, app_reads=328, hits=243, misses=82, underflow=0`。

### official APUG011 compatibility

最终：`PASS(24)`。读回：

```text
addr=5 -> 0x11223344
addr=8 -> 0xA5A55A5A
```

并通过 model-safe tCK/tRCD、read DQM、outstanding/protocol checks。

## 3. 板级 bring-up 过程

### 3.1 一直停在 P1-04C 八色条

说明 HDMI golden boundary 存活，但 framebuffer activation 条件未完成。

### 3.2 全屏洋红

诊断 mux 将 read/display protocol error 映射为洋红。根因候选定位到启动期 prefetch 在两个 ping-pong bank 都占用时过早发起 line2；最终通过 `lb_fill_ready` gate 修正 scheduler。

### 3.3 移动彩色窄线

修正 scheduler 后进入 framebuffer 模式，但真板只显示一条正确颜色窄线向下移动，其余行黑。该现象证明 SDRAM 图像内容和 RGB/order 已经正确到达 HDMI，但 sustained line refill bandwidth 不足。

根因：P1-02 single-word adapter 对每个 abstract pixel 都读取完整 APUG011 4-word group，连续 0/1/2/3 会重复读取同组四次。加入 4-word cache 后，物理读放大降为接近 1 physical word / pixel。

### 3.4 完整 framebuffer

cached adapter 上板后，白边 + 四象限 + 中央十字同时稳定显示，移动黑线消失。最终 timing-fix bitstream 再上板验证后仍稳定，无可见抖动、抽搐或撕裂。

## 4. Timing closure 过程

### 初始 combined build

```text
Overall WNS  -5.320 ns
25 MHz       9 setup errors
150 MHz      9 setup errors
```

25 MHz 问题包含 150→25 MHz diagnostic/status 组合跨域与 async-FIFO crossing 被按同步路径分析。

### CDC 修正

- status 信号在 pixel side 同步；
- SDC 用 TD5.6.2 实际 derived-clock 名称声明 25 MHz pixel 与 150 MHz SDRAM 为 asynchronous groups；
- 不对 150 MHz same-domain path 使用 false path。

结果：25 MHz TNS 清零，只剩 150 MHz 9 个 setup error，overall WNS `-0.743 ns`。

### 150 MHz RTL 修正

cached adapter 写入口改为 registered request slice，删除上游 payload compare 对 backend progress 的组合反馈。

最终 TD5.6.2：

```text

Setup errors      0
Hold errors       0
Setup WNS        +0.068 ns
Setup TNS         0.000 ns
Hold WHS         +0.131 ns
Hold TNS          0.000 ns
```

时钟：

```text
25 MHz  Min Period 27.015 ns, Max Freq  37.000 MHz, TNS 0
```

## 5. FIX4 verification-harness 修正

registered write handshake 改变后，两个老 TB 在 `negedge` 同时拉高 `valid` 并读取组合 `ready`，出现 delta-cycle race，导致 cache-hit/accept counter 人工重复。实际 readback 与 provider transaction 均正确。

FIX4 将 valid/ready transfer 统一在 `posedge clk` 判定、下一 `negedge` 撤销 valid。最终三项全部通过：

```text
p1_sdram_cached_adapter                  PASS(58)
p1_sdram_hdmi_cached_chain               PASS(260)
p1_sdram_cached_adapter_apug011_official PASS(24)
```
