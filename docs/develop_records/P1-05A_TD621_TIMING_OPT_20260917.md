# P1-05A TD6.2.1 Timing Optimization Record — 2026-09-17

## 1. Context

官方要求工具链从 TD5.6.2 切换到 TD6.2.1。P1-05A 的功能 golden baseline 没有改变，但必须重新关注 implementation timing。

本记录只描述 TD6.2.1 迁移与 source-level timing optimization；它不覆盖此前 P1-05A 的 Questa/BitGen/真板 closeout。

## 2. TD6.2.1 pre-optimization evidence

来自本次上传工程中 `FPGA_Competition_HDMI_Runs/phy_1/final_timing.rpt`：

```text
Tang Dynasty v6.2.168116
STA coverage : 99.15%
SWNS         : -7.098 ns
HWNS         : +0.011 ns
150 MHz SWNS : -1.119 ns
150 MHz HWNS : +0.182 ns
```

150 MHz self-domain 的软件 worst path 落在：

```text
u_sdram_hdmi_pipeline/u_read_cdc/u_req_fifo/ramread0
    -> u_sdram_adapter/protocol_error_reg
```

该路径在 synthesis timing report 中约为 9.341 ns data-path delay，8 个 logic levels。大量逻辑来自 `p1_sdram_cached_adapter` 的 sticky diagnostic/protocol bookkeeping，而这些信号不是 framebuffer data path。

整体 `SWNS=-7.098 ns` 的 worst path 则来自 APUG011/internal SDRAM hard-I/O 的 `u_sdram_pll/pll_inst.clkc[2] -> clkc[1]` setup analysis；该路径 data path 主要是 hard IP / I/O delay，routed `HWNS` 仍为正，因此本轮不使用 false-path 去掩盖它。

## 3. Optimization A — production diagnostic compile-out

`src/framebuf/p1_sdram_cached_adapter.v` 新增：

```verilog
parameter integer ENABLE_RUNTIME_DIAGNOSTICS = 1
```

默认值保持 `1`，所以已有 Questa 单模块和 integration TB 的行为不变。

P1-05A board top 使用：

```verilog
.ENABLE_RUNTIME_DIAGNOSTICS(0)
```

生产版仍保留 provider response legality check；仅将 contention/debug counters 和冗余 assertions 从 production 150 MHz cone 中排除。目标是消除 TD6.2.1 synthesis timing report 中由 diagnostic bookkeeping 形成的长路径，而不是改变 SDRAM cache/read/write protocol。

## 4. Optimization B — reset release phase (superseded experiment)

旧实现使用 50 MHz `posedge clk` 释放 `hdmi_rst`。TD6.2.1 routed report 的最差 pixel-domain removal check 只有：

```text
HW slack = +0.011 ns
```

该 endpoint 位于官方 APUG092 protected HDMI core 的 reset path。P1-04C 的 HDMI low-level protocol 不需要改变，只需把 reset release phase 移开。

初始候选曾将 reset hold counter 改为在 `negedge clk` 工作：

```verilog
always @(negedge clk) begin
    ...
end
```

这仍保持约 20 ms 的 reset hold，但 TD6.2.1 后续报告显示下降沿释放使 125 MHz serial-domain recovery window 只剩约 2 ns，并产生 recovery violation。因此当前实现已恢复官方例程的 `posedge clk` 释放；该实验不能作为最终时序优化结论。

## 5. Verification status

本环境没有安装 TD6.2.1 executable，因此本轮无法在容器内重新执行 TD synthesis/P&R/BitGen，也无法声称新的 `[S]`/`[B]`。

必要验证顺序：

1. TD6.2.1 full synthesis + P&R；
2. final STA：重点观察 pixel removal、150 MHz same-domain setup/hold，以及 hard SDRAM clock relationship；
3. Questa full P1-05A regression；
4. BitGen；
5. HX4S20C 真板：完整 framebuffer、无 underflow、无移动彩线/撕裂。

在上述证据完成前，P1-05A 的正式 `[S][B] CLOSED` 仍指向 TD5.6.2 historical closeout。
