# M2.1 · 后台提前预读（2026-10-06）

本记录对应 `M2_UI_FAST_INTEGRATION_20261006` 的增量修改。当前显示 profile 仍为 **640×480**；本记录不改变 1080P 目标，也不提供新的真板 `[B]` 证据。

## 行为契约

- 当前图片显示期间，主板控制器在没有用户操作时请求下一张图片的预读。
- 从板使用现有 TF → 14 线图片传输，把预读帧发送到主板非前台缓存槽。
- 预读帧只有在 CRC、写入 fence、缓存元数据和安全提交条件全部满足后才置为有效；不会改变当前显示图片，也不会显示 Loading UI。
- K2/K3 或自动轮播请求优先于预读。用户请求到达时，待发预读被取消；正在进行的传输不会被当作前台显示完成。
- 预读完成状态采用从板粘滞状态，保持到下一次 OPEN，避免跨板时钟和 UART STATUS 轮询漏掉单周期完成脉冲。
- 预读命中已有缓存时只完成查询，不产生重复 OPEN，也不触发前台字幕/OSD 提交。

## 协议和 RTL

| 层 | 修改 |
|---|---|
| C 线命令 | `media_command_controller` 增加 `ENABLE_PREFETCH`、普通事务/预读事务状态和用户优先级仲裁 |
| 控制 UART | `OPEN` 长度 2 的 payload 携带 mode；`mode=1` 表示预读 |
| B 线帧协议 | 预读帧使用 `B17E02xx`，普通 compact 帧继续使用 `B17E01xx` |
| 主板缓存 | 预读帧写非 front bank；只在显式缓存查询命中后切换显示 bank |
| 从板完成反馈 | 预读完成 ID 粘滞，`STATUS=DONE` 直到下一次 OPEN |
