## Diagnostic change

`m2_slave_tf_hdmi_top.v` now counts accepted loader->write-CDC words at 25 MHz. A valid 640x480 frame is exactly 307200 words. If the legacy generic loader error `0x15` recurs, the LEDs no longer show ambiguous `5`:

- `9`: accepted words = 0; failure is at BMP/header/writer-arm boundary.
- `C`: 1..307199 accepted words; failure is mid-frame/backpressure/protocol.
- `E`: >=307200 accepted words; full pixel payload crossed the loader/CDC boundary and the failure is terminal/fence consistency.

Existing detailed `0x39..0x3D` errors still display their native low nibble `9..D`. `F` remains SDRAM backend error; `1..8` retain their prior meanings.

This counter does not enter the 150 MHz SDRAM timing cone.

Interpret RED with this build:

- 9 => inspect BMP header/parser and writer arming;
- B => unsupported/corrupted BMP/header path (native 0x3B);
- C => loader pixel arrived while writer was not ready, or generic 0x15 failed mid-frame;
- D => writer FIFO overflow;
- E => all frame words crossed loader->CDC but terminal/fence consistency failed;
- F => SDRAM arbiter/adapter/provider sticky error.
