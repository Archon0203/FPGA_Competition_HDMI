# M2 TF DIAG4 - unambiguous board diagnostics

> **开发过程/候选记录：保留当时的现象、推断和修复方案，不作为当前 PASS 状态权威。当前状态以 `docs/03_plan_and_status.md` 为准。**


Date: 2026-10-03

## Reason

The board has two independent LED resources.  `6_EX_DEVICE.pdf` shows the four
green LEDs LED1..LED4 driven from FPGA nets LED0..LED3 through 1 kOhm resistors
to LEDs returning to ground, so they are active-high.  `2_FPGA.pdf` maps those
nets to A4/A3/E13/B12.  Therefore physical LED1+LED3 means logic `0101`.

The board also has an 8-bit dual-color LED group in `5_DIG_VGA.pdf`.  Its LEDVCC
feeds the LED anodes through 470 Ohm resistor arrays and FPGA DIG/SEL nets sink
current, so those nets are active-low.  SW6 selects LED versus nixie-tube power.

A DIAG3 red page plus four-LED `0101` would imply media failure byte `0x15`, but
the DIAG3 source no longer generates legacy `0x15`.  This makes the four-bit
overloaded diagnostic insufficient to distinguish a stale build/source mismatch
from a data-path failure.

## DIAG4 mapping

Four active-high LEDs are fixed state bits:

- physical LED1 / `led[0]`: FAT catalog valid;
- physical LED2 / `led[1]`: media loader busy;
- physical LED3 / `led[2]`: SDRAM frame fenced/ready;
- physical LED4 / `led[3]`: any media or SDRAM/write fault.

The eight-LED DIG color displays a complete byte, active-low in hardware:

- no fault: `0x81` build marker (the two end DIG LEDs are on);
- media fault: exact `media_failure_code`;
- SDRAM/write fault: `0xF0`.

`diag_sel_n` is driven `0xFF` to disable the alternate color / nixie select path.
No counters, RAMs, FIFOs or additional state machines are added.

Pin mapping (DIG0 is diagnostic bit 0):

`DIG0..7 = C15,C16,B6,A5,B5,A8,A7,A6`

`SEL0..7 = F16,E16,E12,E10,C13,F10,E11,D11`
