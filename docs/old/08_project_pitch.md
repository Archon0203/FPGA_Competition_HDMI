## 0. 作品名称

**《基于 EG4S20 的 HDMI 多媒体播放系统——校园/园区信息发布与应急广播终端》**

## 1. 项目概述（一段话）

本项目基于安路 EG4S20 FPGA 开发板（HX4S20C），设计并实现了一款 HDMI 多媒体播放系统，
利用 FPGA 并行处理优势，实现从 **SD/TF 卡读取媒体内容 → FPGA 缓存 → 图像处理 → HDMI 编码 → 显示器输出** 的全流程硬件加速，
**全程不依赖外部处理器**。系统以“信息发布与应急广播终端”为应用场景，支持图片轮播、短视频片段、
时间戳与滚动标语叠加、亮度/对比度实时调节、转场特效、音频输出与音频可视化，并可一键进入应急广播。

## 2. 三大功能模块与数据流

```
 SD/TF卡 ──▶ [模块A: SD读取] ──▶ [模块B: 视频/图像处理] ──▶ [模块C: HDMI驱动] ──▶ 显示器
            SPI读卡/文件系统/解帧     FPGA帧缓存 + 图像处理       TMDS编码/串行化

  数据流： SD卡 → FPGA缓存(帧缓冲/SDRAM) → 图像处理(YCbCr→RGB+缩放+增强) → HDMI编码(TMDS) → 显示
```

| 模块 | 职责 | 对应 RTL 子目录 |
|---|---|---|
| **A. SD 卡读取** | SPI 读卡；FAT32 解析；BMP 解析；`.vseq` 视频帧序列解析 | `src/storage` |
| **B. 视频/图像处理** | 帧缓冲(SDRAM, 双/三缓冲)；**YCbCr→RGB 色彩空间转换**；**图像缩放**；亮度/对比度增强；转场/OSD 叠加 | `src/framebuf` + `src/display` |
| **C. HDMI 驱动** | 行场时序；**TMDS 编码**；串行化输出 | `src/display`（tmds_encoder） |

> 三大模块是“功能抽象”；实现时每个模块继续细分为子模块（见 `src/` 目录），并在内部并行流水线。

## 3. 关键技术实现

### 3.1 色彩空间转换（YCbCr→RGB）
- 视频帧以 YCbCr（YUV）存储，按 BT.601 矩阵转 RGB：
  ```
  R = Y + 1.402(Cr-128)
  G = Y - 0.344(Cb-128) - 0.714(Cr-128)
  B = Y + 1.772(Cb-128)
  ```
- 定点化（用移位/乘法器）实现；YUV420 需先做色度上采样（最近邻/双线性）。
- 采用行缓存(line buffer)流水线，逐像素处理。

### 3.2 视频/图像缩放
- 任意输入分辨率 → 输出分辨率；最近邻（低资源）/双线性（高质量）可切换。
- 短视频片段（如 320×240 YUV420）放大到 640×480 输出。

### 3.3 TMDS 编码与串行化
- 采用 TMDS（最小化传输差分信号）10bit 编码，3 数据通道 + 1 时钟通道；复用官方 `lab_ex` 的 OSERDES/串行化参考。
- **是否能用 720p/1080p 视 FPGA IO 与板卡约束而定（见第 5 节边界）。**

### 3.4 PLL & 像素时钟
- 板载 50MHz + PLL 生成 `clk_sys`/`clk_pix`/`clk_tmds`/`clk_sdram`/`clk_sdo`/`clk_aud`。
- 像素时钟可配置以适配不同输出分辨率（640×480 基线，向 720p 扩展验证）。

### 3.5 流水线并行与模块化
- 一帧或多行流水线并行处理，吞吐率＝像素时钟；模块间用 FIFO/握手解耦。
- 预留“算法切换/扩展”接口（`menu_fsm` 下发算法/参数选择，`display` 流水线按选择路由），便于“图像增强/边缘/卡通”等功能迭代。

## 4. 核心卖点（已校准口径）

1. **纯硬件逻辑，不依赖外部处理器**：读卡→缓存→处理→编码→显示全流程在 FPGA 内完成，契合赛题红线。✅可斩钉截铁
2. **显示输出流水线像素级低延迟（微秒级）**：帧缓冲→TMDS 输出为像素/行级流水，物理上可达微秒级。⚠️限定为“输出流水线”，**勿说成“整条 SD→显示链路微秒级”**（那是帧级）。
3. **PLL 灵活生成像素时钟**，支持输出分辨率可配置。⚠️以 640×480 稳定基线，720p 尽力验证，**1080p 不纳入承诺**。
4. **流水线并行架构提升吞吐率** 且 **模块化预留算法扩展接口**，便于功能迭代与扩展项叠加。✅可强调

> 一句话卖点：“无需 CPU，单块 EG4S20 用硬件流水线把 SD 卡里的图片/短视频读、转、缩、编、显示，做到确定性低延迟与可配置输出。”

## 5. ⚠️ 关键技术边界（答辩前必须知道，避免翻车）

| 说法 | 客观事实 | 建议口径 |
|---|---|---|
| “SPI 采集视频帧数据” | SPI @25MHz≈3.1MB/s，**无法实时流式播放** 720p/1080p 视频 | 改说“SPI 读卡用于图片与预载帧序列；短视频片段采用**预载循环/低分辨率 SDIO**” |
| “适配 720p/1080p” | 720p/1080p 的 TMDS 位时钟分别为 ~742/1485MHz，靠 FPGA 逻辑串行化有风险；官方样例仅 640×480 | 讲“**640×480 稳定基线 + 可配置输出，向 720p 扩展验证**”；1080p 列为探索项 |
| “延迟达微秒级” | 端到端“SD→显示”是**帧级**（帧率/预载决定）；只有“输出流水线”是像素/行级微秒级 | 限定“显示输出流水线像素级微秒级低延迟” |
| “视频解码” | 本板**不能解码**压缩视频(H.264/MP4) | 表述“短视频片段/图片/动画”，**不提“视频解码/MP4 播放”** |

> 评委极可能问：“为什么不用/不行 H.264？多大分辨率？延迟多少？”——请按上表口径回答，并报出**实测分辨率/帧率/延迟/资源占用**。

## 6. 明确应用场景（承接 docs/07）

**校园/园区“信息发布与应急广播终端”**：
- 常态：公告图片轮播 + 宣传短视频片段 + 当前时间 + 滚动标语 + 背景音；按键切上/下张、播放/暂停、切换图片/视频源；拨码调亮度/对比度、切转场、开关 OSD；数码管显示状态、双色 LED 指示。
- 应急：一键切换“应急画面 + 大字警告 + 蜂鸣 + 应急提示音”，强调**毫秒级确定性**。

## 8. 建议对外指标（以实测为准）

- 输出：640×480@60（基线；720p 扩展验证）
- 源：图片(BMP) + 短视频片段(YCbCr/`.vseq`)
- 资源：待综合后填报（LUT / DFF / ERAM / SDRAM / PLL / 时序余量）
- 稳定性：连续运行≥2h；快速切换无花屏
- 延迟：输出流水线微秒级；SD 预载/切换为帧级（实测值）
